# essola lab — инструкция для ИИ-ассистента, который продолжает работу

Этот файл — передача дел. Прочитай его целиком, прежде чем что-то запускать или менять.

## 1. Что это за проект

- Мобильное приложение **essola lab** (Expo SDK 57, expo-router, TypeScript), папка `app/`.
  Сканер составов косметики, лента рецептов, конструктор формул, база средств, форум, статьи.
- Владелец — новичок, тестирует через **Expo Go** на iPhone. Всё технически делает ассистент, объясняет простыми словами, по-русски.
- Сервер — облачная функция Yandex Cloud `essola-scan`, код в `server/yandex-scan/index.js`.
  Данные лежат в Yandex Object Storage, бакет `essola-products-<YC_FOLDER_ID>`.
- Рабочая ветка: **`claude/awesome-mccarthy-dlbgor`**. Коммиты и пуши только в неё. Pull request не создавать, если владелец не попросит.

## 2. Правила безопасности (обязательно)

- **Никогда не просить владельца прислать ключи, токены или `authorized_key.json` в чат.**
  Все секреты уже лежат в GitHub → Settings → Secrets: `YC_SA_KEY`, `YC_FOLDER_ID`, `EXPO_TOKEN` и др.
  Работать с ними только через GitHub Actions.
- Каталог Летуаль собирается **с разрешения Летуаль** (владелец получил его от компании).
  Не обходить антибот-защиту других магазинов (Золотое Яблоко и т. п.) и не собирать их массово.
- Не выдумывать «пользовательский» контент: фейковых пользователей, отзывы, рецепты «от участниц».
  Редакционный контент подписывается как **essola lab**.
- Администратор в коде определяется по sha256 email, сам email в код не писать.

## 3. Автоматика (GitHub Actions)

| Workflow | Файл | Когда запускается | Что делает |
|---|---|---|---|
| EAS Update | `.github/workflows/eas-update.yml` | при каждом пуше в ветку | публикует обновление приложения для Expo Go |
| Deploy AI scan function | `.github/workflows/deploy-scan.yml` | при изменении `server/` | выкатывает облачную функцию + смоук-тесты |
| **Letual catalog** | `.github/workflows/letu.yml` | вручную или по расписанию (вс 01:23 UTC) | собирает базу Летуаль |

### Как устроен сбор Летуаль (`letu.yml`)

1. `roots` — список разделов сайта (скрипт `app/scripts/letu-crawl.mjs roots`).
2. `list` — по одному роботу на раздел, собирают карточки товаров (до ~2 ч).
3. `tabs` — 10 роботов параллельно скачивают составы. Товары, которые уже есть в базе, пропускаются (режим «продолжения»), лимит ~5,5 ч.
4. `build` — объединяет новое со старой базой (`app/scripts/build-letu.ts`) и загружает в бакет:
   - `letu/index.json` — карточки (название, бренд, фото, ссылка, категория, оценка, отпечаток состава `g`);
   - `letu/x/<hhh>.json` — составы (4096 файлов);
   - `exports/letu.csv.gz` — вся база таблицей для владельца.

Время полного прогона: 3–7 часов. Даже если робот упрётся в лимит, собранное сохраняется, а следующий запуск продолжит с того же места.

### Как запустить

**Через сайт GitHub (может сделать и владелец с телефона):**
Репозиторий → **Actions** → **Letual catalog (with Letual's permission)** → **Run workflow** → ветка `claude/awesome-mccarthy-dlbgor` → **Run workflow**.

- Обычный запуск (галочка `build_only` выключена) — дособирает новые товары и составы.
- `build_only` = включено — **без обхода сайта**, только пересобирает индекс из того, что уже лежит в бакете (~15 мин). Нужен, например, после изменения `build-letu.ts`.

**Через API** (если у ассистента есть доступ к GitHub API):
```
POST /repos/alexeyberdus-eng/essola/actions/workflows/letu.yml/dispatches
{"ref": "claude/awesome-mccarthy-dlbgor", "inputs": {"build_only": "false"}}
```

Одновременно может идти только один сбор (`concurrency: letu`); новый встанет в очередь.

### Как проверить результат

- Actions → последний запуск → job **build** → в конце лога строки:
  `kept from the existing base N`, `fingerprints N`, `letual items N shards N {...по категориям}`, `index HTTP 200`.
- Число `letual items` — размер базы Летуаль в приложении (на 03.10.2026 было **65 695**).
- В job **tabs (N)** строки `shard N: X/Y, with composition Z` показывают прогресс (видны только после завершения job).

## 5. Известные проблемы и следующие задачи

1. **Разделы «Волосы», «Для мужчин», «Аптечная», «Корейская», «Органическая», «Для дома» дают 0 товаров.**
   Меню сайта (`/api/content-delivery/v1/public/header/top-menu`) из GitHub не отвечает, и `roots` берёт
   запасной список `ROOTS` в `letu-crawl.mjs`, где пути этих разделов неверные. Рабочие: `/browse/uhod-za-kozhei`, `/browse/makiyazh`, `/browse/parfyumeriya`.
   Задача: найти настоящие пути (например, через `POST /api/searcher/v1/filters` для корня каталога — в ответе дерево `categories` с полем `path`),
   исправить `ROOTS`, запустить обычный сбор. Логи `list` покажут `walk <путь> <число> pages`.
2. Если в логе `tabs` много `HTTP 504` — это перегрузка сайта; скрипт сам повторяет запросы. Не увеличивать параллельность.
3. Репозиторий **публичный**. После окончания сбора напомнить владельцу сделать его приватным
   (Settings → General → Danger Zone → Change visibility). Учесть: у приватных репозиториев 2000 бесплатных минут Actions в месяц.
4. Партнёрская программа Летуаль: когда владелец пришлёт шаблон партнёрской ссылки — обернуть им все ссылки на letu.ru (`u` в индексе / кнопка «Купить в Летуаль»).
5. Золотое Яблоко в сканере работает через видимую WebView (`app/src/components/ShopPage.tsx`) и запасной вариант «скриншот». Проверять на телефоне.

## 8. Требования App Store (сделано в приложении)

- Удаление аккаунта: Кабинет → «Удалить аккаунт» (`app/src/lib/moderation.ts` → `deleteAccount`): серверный режим `user.delete` удаляет профиль, рецепты, подписки и уведомления, сообщения форума обезличиваются, данные на телефоне стираются.
- Чтобы удалялась и сама учётная запись входа в Supabase, один раз выполните в Supabase → SQL Editor:
  ```sql
  create or replace function public.delete_user() returns void
  language sql security definer set search_path = public as $$
    delete from auth.users where id = auth.uid();
  $$;
  grant execute on function public.delete_user() to authenticated;
  ```
- Пользовательский контент: «…» у тем, ответов и отзывов → «Пожаловаться» (сервер `report` → `reports.json` в бакете) и «Скрыть пользователя» (на устройстве). Перед первой публикацией нужно принять правила. Мат отклоняется сервером (`error: rude`).
- Экран `/legal`: правила сообщества, политика конфиденциальности, условия. Для App Store Connect нужна ещё публичная ссылка на политику (например, страница на essola.ru с тем же текстом) и ссылка поддержки.
- Жалобы нужно разбирать в течение 24 часов (так написано в правилах): файл `reports.json` в бакете.

## 9. Вход через VK ID

- Код: `app/src/lib/vk.ts` (OAuth 2.1 + PKCE, без секрета), кнопка на экране `/auth`, аккаунт сохраняется на телефоне (`vk:<id>`).
- VK возвращает код на https-адрес облачной функции (GET), функция перенаправляет его обратно в приложение (`exp://` или `essola://`).
- Чтобы кнопка появилась: владелец создаёт приложение на id.vk.com/business (тип «Веб» или «Мобильное»), в «Доверенный Redirect URL»
  указывает `https://functions.yandexcloud.net/d4eikcrvo6v275frt26v`, а ID приложения кладёт в GitHub Secrets как `VK_CLIENT_ID`. Следующий пуш — и кнопка в приложении.

## 11. «Честный знак» (Национальный каталог)

- Сканер → режим «Честный знак»: DataMatrix → GTIN (после «01») → серверный режим `nk` → официальный API НК `GET /v3/product?gtin=…&apikey=…`
  (апи.национальный-каталог.рф). Ключ участника (ИП владельца) — в GitHub Secrets `NK_API_KEY`, в код не попадает.
- Если в карточке нет состава — поиск по названию в базе Летуаль и в интернете (`findByLabel`). Ответы кэшируются в бакете (`nk/<gtin>.json`).
